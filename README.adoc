= mfsbsd-se
:toc: left
:toc-title: Table des matières

Images https://github.com/mmatuska/mfsbsd[mfsBSD] SE (« special
edition » : avec `base.txz` et `kernel.txz` de la release embarqués)
pour les releases FreeBSD que le projet mfsBSD ne publie pas, ou pas encore.

Le projet mfsBSD est tenu par une seule personne. Sa dernière publication
(20 janvier 2026) s'arrête à 15.0, sans 14.4 ni 15.1. Ce dépôt reprend
exactement sa construction (`ci/ci.sh`, cible `build-se`) pour d'autres
versions, sans rien y changer : mêmes sources, même mot de passe root par
défaut (`mfsroot`), même nom d'image.

L'image sert notamment à https://github.com/aloli-crystal/beryl-cli[beryl]
(`beryl bootstrap`), qui installe FreeBSD depuis le système de secours d'un
hébergeur.

== Construire et publier

Onglet *Actions* → *Image mfsBSD SE* → *Run workflow*, version `15.1`, ou :

[source,sh]
----
gh workflow run build.yml --repo papilip/mfsbsd-se -f version=15.1
----

Le flux (`.github/workflows/build.yml`) :

. démarre une machine virtuelle FreeBSD de la version demandée
  (https://github.com/vmactions/freebsd-vm[vmactions/freebsd-vm]) ;
. y lance `build-mfsbsd-se.sh` : sources de mfsBSD au commit de sa
  dernière publication, `base.txz` et `kernel.txz` de la release depuis
  `download.freebsd.org` (https), vérifiés par le `MANIFEST` de la release,
  puis `make iso SE=1 ROOTHACK=1` ;
. publie la release `mfsbsd-se-<version>` : l'image
  `mfsbsd-se-<version>-RELEASE-amd64.iso`, son empreinte (`.sha256`) et le
  journal de construction.

Une release existante n'est jamais écrasée : pour reconstruire, supprimez-la
d'abord. Les actions sont épinglées par commit.

== Nouvelle version de FreeBSD

Une image par release, publiée une seule fois (`mfsbsd-se-<version>`).

. *Sources de mfsBSD.* `build-mfsbsd-se.sh` épingle un commit de mfsBSD
  (`MFSBSD_REF`, aujourd'hui celui de sa publication du 20 janvier 2026).
  Pour une nouvelle majeure, regarder si le projet a corrigé sa
  construction depuis (https://github.com/mmatuska/mfsbsd/commits[ses
  commits]) ; si oui, relever `MFSBSD_REF` sur le commit voulu, commiter
  et pousser *avant* de lancer le flux. Pour une mineure, le commit épinglé
  suffit en général.
. *Machine virtuelle.* Vérifier que
  https://github.com/vmactions/freebsd-vm#readme[vmactions/freebsd-vm]
  propose la release. Sinon, construire à la main (ci-dessous) sur une
  machine FreeBSD de la même majeure, puis publier à la main la release
  `mfsbsd-se-<version>` avec l'image et son `.sha256`.
. *Construction et publication* :
+
[source,sh]
----
gh workflow run build.yml --repo papilip/mfsbsd-se -f version=16.0
gh run watch --repo papilip/mfsbsd-se
----
+
Pour reconstruire une version déjà publiée (correctif de mfsBSD, image
défectueuse) : supprimer sa release et son étiquette, puis relancer.
L'empreinte change : la configuration des utilisateurs de l'image est à
mettre à jour.
+
[source,sh]
----
gh release delete mfsbsd-se-16.0 --repo papilip/mfsbsd-se --cleanup-tag
----
. *Contrôle.* Vérifier l'empreinte et le contenu de l'image publiée :
+
[source,sh]
----
B=https://github.com/papilip/mfsbsd-se/releases/download/mfsbsd-se-16.0
curl -fLO $B/mfsbsd-se-16.0-RELEASE-amd64.iso -fLO $B/mfsbsd-se-16.0-RELEASE-amd64.iso.sha256
shasum -a 256 -c mfsbsd-se-16.0-RELEASE-amd64.iso.sha256
bsdtar tf mfsbsd-se-16.0-RELEASE-amd64.iso | grep -E 'base.txz|kernel.txz|mfsroot'
----
. *Utilisation.* Les notes de la release donnent les trois lignes de
  configuration beryl (`mfsbsd_url`, `mfsbsd_version`, `mfsbsd_sha256`).
  Côté beryl, la marche à suivre complète (quand une nouvelle image est
  nécessaire, déclaration dans chaque société, validation) est dans
  `docs/mfsbsd-maison.adoc` de
  https://github.com/aloli-crystal/beryl-cli[beryl-cli].

== Construire à la main

En root, sur une machine FreeBSD de la même majeure que l'image :

[source,sh]
----
sh build-mfsbsd-se.sh 15.1
----

L'image et son empreinte sont écrites dans `/var/tmp/mfsbsd-se-15.1/`.
Variables : `MFSBSD_REF` (commit de mfsBSD), `FREEBSD_MIRROR`, `WORKDIR`.

== Utiliser l'image avec beryl

Dans le `_defaults.yml` de la société (configuration beryl), d'après les
notes de la release :

[source,yaml]
----
mfsbsd_url: https://github.com/papilip/mfsbsd-se/releases/download/mfsbsd-se-15.1/mfsbsd-se-15.1-RELEASE-amd64.iso
mfsbsd_version: "15.1"
mfsbsd_sha256: <empreinte de la release>
----

beryl vérifie l'empreinte dans le système de secours avant de démarrer
l'image.
